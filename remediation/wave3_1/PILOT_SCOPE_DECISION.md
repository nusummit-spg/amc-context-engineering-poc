# AMC Wave 3.1 — Pilot Scope Decision (WP00 / gate G0)

**Status: PROPOSED. Not approved.** This records the narrowest scope the design supports, so the
owners can accept or change it. Every sign-off line below is deliberately empty: an engineering
document cannot approve its own product scope.

Source of the scope: [Action Plan §0](MVP_REMAINING_ACTION_PLAN_V1.md) and
[Technical Design §2.2 and §11](MVP_TECHNICAL_DESIGN_SPEC_V1.md). Nothing here widens them.

## 1. What the pilot is

A **controlled, single-deployment, authenticated, read-only verified-publication Q&A pilot**.
An explicitly scoped tenant's users log in, ask questions answered through the v2 engine over a
verified corpus, see grounded citations as provenance, and see limited publication status.

Publication (loading a new corpus generation) is an **operator action performed offline/CLI**.
It is not exposed to ordinary users and has no HTTP mutation endpoint in the pilot.

## 2. In scope (allowed in `AMC_VERIFIED_SERVING_MODE=enforce`)

| Capability | Routes |
|---|---|
| Sign in / out, who am I | `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/me` |
| Ask a question | `POST /api/query`, `POST /api/query/v2`, `POST /api/query/stream` |
| Multi-turn chat | `POST /api/chat`, `POST /api/chat/query`, `POST /api/chat/v2`, `POST /api/chat/stream` |
| Publication status for the caller's tenant | `GET /api/publication/status/{work_id}` |
| Liveness | `GET /health`, `GET /api/health` |
| Static UI | `/`, `/chat`, `/login`, `/assets/*`, `/static-files/*` |

The exact allowlist is `backend/app/api/pilot_perimeter31.py`; this table must match it.

## 3. Out of scope (denied or disabled in the pilot)

Self-service ingestion and upload, feedback capture and repair, correction approval and governance
actions, graph explorer, document and raw-file download (`/api/files`, `/files`, `/api/docs`),
taxonomy browser, scheme aggregation, admin endpoints, user-management screens, WebSockets, the
legacy query engines (`traditional`, `contextgraph`, canary, shadow), automatic graph repair,
multi-tenant SaaS operation, and any 24/7 availability or SLO commitment.

**Known UI consequence.** The stock frontend calls routes the pilot denies, for example the chat
session list (`GET /api/sessions`) and chat titles (`POST /api/chat/title`). See
[FRONTEND_PILOT_COMPATIBILITY.md](FRONTEND_PILOT_COMPATIBILITY.md) (44 denied call sites against 7
allowed). A browser walkthrough of the real pilot stack found that, without handling, the UI also offered
every denied page and one of them (Compliance Scorecard) showed built-in sample figures as if they were live.
The pilot build (`VITE_AMC_PILOT_MODE=true`) therefore shows Chat only, refuses the denied calls itself and
derives chat titles locally; chat history then lives in the browser only. The walkthrough was one manual
session in one browser engine, not an automated cross-browser test.

## 4. Test contract (synthetic only)

Defined and hash-pinned in [TEST_FIXTURE_MANIFEST.json](TEST_FIXTURE_MANIFEST.json), generated by
`python -m tools.amc_release.fixtures31`.

- Tenants: `tenant_alpha` (the pilot tenant) and `tenant_beta` (the adversary, used only to prove isolation).
- Users: `alpha_analyst` (user), `beta_analyst` (user), `alpha_operator` (admin). No passwords or tokens
  are stored anywhere in Git; test credentials are generated at run time and kept in process memory.
- Corpus: four invented factsheet-style documents per tenant, three of them sharing document IDs
  across tenants with different content, in two generations (A active, B staged).
- Failure cases: six tamper descriptors and six fault-injection hooks; the binary index, signing key
  and signature are built locally and disposably at test time, never committed.
- No real fund, customer or personal data is used anywhere in qualification.

## 5. Decisions taken by default (change them here if wrong)

| # | Question | Default assumed | Why |
|---|---|---|---|
| Q1 | Is read-only Q&A enough for the first MVP, or is user ingestion required? | Read-only is enough | Smallest attack surface; ingestion would make this a different, larger release |
| Q2 | Citations: metadata only, or a receipt-bound document viewer? | **Metadata only** (non-clickable provenance) | Raw file routes stay denied; implemented behind `VITE_AMC_PILOT_MODE=true` |
| Q3 | One tenant or true multi-tenant? | One pilot tenant; isolation still tested with two | The design requires proving isolation, not operating many tenants |
| Q4 | Who may publish, revoke, recover, sign? | **Unassigned** | Needs a named owner before any pilot |
| Q5 | Performance and SLO thresholds? | **Undefined** | Define only after measuring on the intended host |
| Q6 | Is an isolated staging environment available? | **Unknown / assumed no** | Without it, acceptance stays blocked |
