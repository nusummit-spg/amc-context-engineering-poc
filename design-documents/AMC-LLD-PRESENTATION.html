System Overview & Design Principles

A governed feedback and self-healing system for an AMC chatbot. User corrections improve the knowledge graph automatically, within strictly bounded safety constraints and full compliance traceability. The core objective: deterministic-first, evidence-first, compliance-aware, LLM-last.

Design Philosophy

The system is structured around a prevention-first cascade. Cheap deterministic checks run first and stop escalation as soon as a decisive result is available. LLM evaluation is reserved for genuine semantic ambiguity â€” targeting 2â€“5% of traffic at maturity. Every novel failure that is understood gets converted into a deterministic rule, making the system progressively cheaper to operate over time.

LLD-02 â€” Evidence Capture (EvidencePack D0â€“D3)

The EvidencePack is the foundational object of the entire evaluation system. It is created immediately after every response is generated and freezes the exact information state at that moment. Without this freeze, an evaluator running hours later would assess the response against updated sources â€” making root-cause attribution unreliable and audit trails meaningless.

â„¹
The governing rule A later change to NAV, TER, source document, graph edge, policy, model version, or taxonomy must not retroactively alter the evidence used to judge an older response. All evaluators reference the same frozen D2 object â€” never re-fetch independently.

Four Components

D0

Response Finalization

Captured the moment the response is assembled. Records identity and operational metadata: response_id (UUID), model version, prompt template version, citations shown, disclosures shown, guardrail state, token counts, tool failures, truncation flag, and response_hash (SHA-256 for tamper evidence).

LLM involvement: None. All fields are operational facts.

~1ms Â· deterministic
D1

Interaction Snapshot

Freezes the system state at response time: raw query, normalised query, detected intent node, intent confidence, extracted entities with canonical IDs, retrieval configuration, taxonomy version, guardrail version, model version, and session metadata (user role, channel, jurisdiction, product context).

PII note: user_query is subject to redaction after 30 days.

~1ms Â· deterministic
D2

Evidence / Provenance Pack

The full evidence record reused by all evaluators. Contains: vector retrieval (chunk IDs, scores, ranks), graph retrieval (nodes, edges, paths), BM25 retrieval, AMC taxonomy matches, context engineering decisions (what was selected vs rejected), source provenance (authority tier, effective dates, content hashes), and 12 pre-computed deterministic metrics.

~5ms Â· no I/O Â· cached in Redis 1h
D3

Resolves the compliance control universe that applies: jurisdiction, regulated entity role, product type, channel, customer segment, interaction mode, advice flag, policy pack ID and version, applicable control set ID, and lists of mandatory controls and hard-block controls. Evidence Sufficiency States

Before any evaluator runs, the evidence state is classified. This prevents evaluators from manufacturing verdicts when evidence is incomplete â€” a critical safeguard against LLM hallucination of facts it cannot verify.

UNVERIFIABLE is a valid and correct verdict. Never invoke an LLM to manufacture a verdict when required evidence is absent. UNVERIFIABLE stops evaluation and logs the reason â€” it does not trigger a repair.

All AMC facts must carry temporal validity. A fact without a valid_from / valid_to range cannot be deterministically checked for freshness, making F05 (source/freshness) failures invisible.

LLD-04 â€” Adaptive Evaluation Router

A deterministic, policy-driven orchestration engine â€” not an LLM and not an agent. It selects the minimum sufficient evaluator for each interaction, stops the moment a decisive result is available, and emits a fully auditable RouterDecision record for every execution.

âš 
Anti-pattern: LLM Router Having an LLM decide what to evaluate introduces nondeterministic evaluator selection, possible mandatory-control omission, difficult reproducibility, harder auditability, and susceptibility to prompt/context variation. The Router must be a deterministic policy engine.

Key Schema Design Decisions

  • D0â€“D3 scalar fields are stored as typed columns (not collapsed into one JSONB blob) to allow indexed querying by jurisdiction, intent, model version, etc.
  • Array/nested payloads (citations, provenance, graph paths) use JSONB â€” flexible schema, queryable with @> operators.
  • correction_audit_trail is append-only â€” no UPDATE or DELETE ever runs against it. 7-year retention enforced at the storage policy level.
  • source_manifests uses a UNIQUE constraint on (source_id, source_version) to prevent duplicate health records.
  • All timestamps are TIMESTAMPTZ â€” timezone-aware, stored in UTC.
