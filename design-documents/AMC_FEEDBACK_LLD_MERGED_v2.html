📐 Unified Approach

Active vs Passive — Integrated Feedback Loop

Both active (user-initiated) and passive (system-detected) signals feed the same evaluation, diagnosis, and governed repair pipeline. Active brings high-specificity signals; Passive brings breadth and coverage. Both are verified against authoritative evidence before any action fires.

🟣

Active Feedback

User explicitly submits feedback — thumbs-down, category selection ("Outdated", "Citation"), highlighted span, or free text. High specificity, low volume.

  • ✅ Specific failure category from user
  • ✅ Highlighted span pointing to exact problem
  • ✅ Free-text correction provided
  • ✅ High-value signal for diagnosis
🔵

Passive Feedback

No user input — system captures metrics on every interaction: retrieval confidence, source freshness, citation integrity, numeric extraction vs source, deterministic checks. 100% coverage, zero user burden.

  • ✅ Source version mismatch detection
  • ✅ Retrieval confidence & empty-retrieval flags
  • ✅ Citation integrity & entailment checks
  • ✅ Numeric consistency validation

🔑
Core principle: Signal ≠ Ground Truth ≠ Action
User feedback is a hypothesis. Passive metrics are correlations. Neither is automatically trusted. Both must be verified against frozen evidence (D0–D3) and authoritative sources before any system change fires. This prevents feedback poisoning and ensures every repair is auditable and reversible.

📐 Deterministic Policy Engine

Adaptive Evaluation Router: E0–E5 Ladder

What needs evaluating, at what depth, under which controls, in what budget. Not an LLM judge—a policy engine that selects minimum sufficient evaluation and stops early with decisive evidence.

Six Router Principles

P1 — Mandatory controls cannot be sampled away
Cost optimisation may reduce evaluation depth for quality checks, but must never bypass an applicable hard AMC/regulatory control (C02, C03, C07, etc.).
P2 — Adaptation means minimum sufficient evaluation
Rule → Semantic → LLM → Agent. Stop as soon as evidence is decisive. Every escalation costs time/tokens; justify each one.
P3 — Evidence sufficiency precedes reasoning
If required evidence is missing, return UNVERIFIABLE instead of asking an LLM to infer truth from incomplete data.
P4 — Regulatory applicability drives routing context
Resolve jurisdiction, entity role, channel, advice mode BEFORE selecting evaluators. The same sentence has different significance in India vs US, retail vs HNI.
P5 — Active incidents short-circuit repeated diagnosis
If this observation matches an existing incident's causal signature, attach to it—don't re-diagnose. Avoids 100s of duplicate LLM calls during systemic failures.

The Five-Level Evaluation Ladder

Level Mechanism Generative Tokens Typical % Use Case
E0 Telemetry only 0 ~100% Healthy low-risk monitoring, infrastructure health, audit trail
E1 Deterministic rules 0 ~100% IDs, dates, numeric reconciliation, citations, versions, disclosures, mandatory controls
E2 Statistical / cohort checks 0 broad Drift detection, anomaly flagging, retrieval-channel disagreement, version correlation
E3 Semantic / NLI / classifier ~0 generative 10–20% Intent classification, entailment, tone, relevance, advice boundary, citation support
E4 Bounded LLM judge controlled 2–5% Nuanced ambiguity unresolved by E3, multi-source conflict summarisation
E5 Agent / Human highest 0.1–0.8% Multi-step investigation, regulatory interpretation, compliance decisions, appeals

Five Explicit Stop Rules

STOP-1 — Deterministic Proof
Authoritative structured source + exact entity + exact temporal context + deterministic mismatch confirmed → verdict established. No semantic model, LLM, or agent required. Example: Response TER=0.79%, canonical source TER=0.82%, source versions differ. F05 confirmed at E1.
STOP-2 — Evidence Absent
Required evidence missing + deterministic recovery unavailable → UNVERIFIABLE. Do not ask an LLM to manufacture a verdict.
STOP-3 — Known Incident
Observation matches active confirmed incident + same causal signature → attach observation → stop repeated root-cause investigation. Avoids hundreds of duplicate LLM diagnoses during systemic failures. Example: Model v3.2 hallucination observations 4–200 all attach to I-047, skip diagnosis.
STOP-4 — Semantic Model Resolves
Semantic/NLI output + within validated domain + confidence ≥ threshold → stop. Example: Citation entanglement check: (claim, cited_chunk) pair runs through NLI, entailment_score=0.04 → FAIL confirmed, no LLM escalation.
STOP-5 — Compliance Requires Human
Policy says HUMAN_REQUIRED → stop automated adjudication → route to compliance/HITL. LLM may assist with evidence summarisation but must not replace the required human decision.

Token Cost Comparison
Naive approach (LLM judge per response): 200 hallucination observations × ~400 tokens = 80,000 tokens.
With incident correlation + numeric extraction + STOP-3: ~1,200 tokens total (first 3 diagnoses, 197 observations attached at zero cost).
For inaccuracy and missing context: 0 tokens regardless of volume — both structurally diagnosable from D2 metrics alone.

📐 Governance Ladder

Repair Decision Tree: R0–R5 Classes

Which repair fires depends on scope, risk, authority, and governance requirements. Auto-safe repairs (R1) need no approval. Structural changes (R3+) require engineering or compliance oversight.

R1 — Auto-Safe Mechanical
Low-Risk, Bounded, Reversible
Source exists in registry. Repair replaces stale value with current authoritative value. Bounded to one entity/attribute. Deterministic validation available. No compliance impact.

Fires for: Inaccuracy (stale TER), simple source refresh
Example: Re-ingest AMFI_v18, update graph edge, invalidate cache. No approval needed.
R2 — Auto + Shadow Validation
Broader Scope, Shadow Verified
Repair is deterministic but affects multiple queries or a pipeline rule change. Shadow validation verifies no collateral damage before promotion.

Fires for: Missing Context (reranker rule), Citation (pre-delivery NLI gate)
Example: Context rule deployed to shadow, 10 queries replayed, coverage improves 2/7→6/7, promoted.
R3 — Engineering Approval Required
Model/Prompt Change, Wide Blast Radius
Repair changes model behaviour, prompt templates, or system components with broad impact. Shadow validation alone insufficient—human engineering decision required.

Fires for: Hallucination (model rollback), prompt engineering changes
Meanwhile: R1 or R2 mitigations applied immediately. R3 queued for engineering sprint.
R4 — Investigative
Conflicting Authority, Ambiguous Causation
Conflicting authoritative sources or causal ambiguity. Agent or SME investigation required before repair attempted.

Example: AMFI says TER=0.82%, old SID still says 0.79% due to update lag. System cannot auto-resolve which is authoritative for which effective date.
R5 — Prohibited Auto-Repair
Regulatory, Legal, Compliance Decisions
Repair requires interpreting a regulatory rule, suitability standard, or jurisdiction applicability. These are legal/compliance determinations—never autonomous.

Example: New SEBI circular ambiguity on disclosure sufficiency. Compliance team interprets and updates rule pack.
R0 — No Repair / Monitor
Feedback Invalid, System Correct
Feedback is invalid, duplicated, or system behaved correctly. Complaint is user preference, not a defect.

Example: User says "I don't like mutual funds" 10 times. No system fault. Marked R0, preserved for audit trail.

The 5 Distinctions That Prevent Wrong Repairs

1️⃣
F07 Hallucination vs F05 Stale Source
F07: Model generated 38%, no chunk has it. F05: Model correctly copied stale 0.79%, canonical now 0.82%. Confusing these → wrong component blamed.
2️⃣
F09 Context Drop vs F04 Retrieval Miss
Drop: Chunk retrieved (top-K) but dropped at reranking (0.58). Miss: Chunk never retrieved. Confusing these → months of re-indexing when fix is one reranker threshold line.
3️⃣
F06 Citation Integrity vs Entailment
Integrity: Citation link exists and resolves (E1). Entailment: Cited content supports claim (E3 NLI). Treating both as "citation problem" misses entailment failures.
4️⃣
Feedback as Claim vs Ground Truth
Claim: User asserts "TER should be 0.82%". Verify against canonical. Truth (wrong): Directly update with user value—causes feedback poisoning. Verification step is non-negotiable.
5️⃣
Isolated Failure vs Incident (Root Shared)
Isolated: One response, one user. Incident: 200 responses, same signature (model version, source version). Without correlation: 200 LLM evaluations. With STOP-3: 1 evaluation + 199 zero-cost attachments.
