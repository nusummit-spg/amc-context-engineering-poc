7 Core Design Principles

1. Deterministic-First

Rules, provenance, numeric checks, and temporal validation run before any semantic model or LLM. If a rule can prove it — stop there. Zero tokens consumed.

2. Evidence-First

An immutable EvidencePack is frozen immediately after every response — query, retrievals, graph paths, citations, source versions. All evaluation uses this snapshot, never re-fetched state.

3. Feedback is a Claim, Not Ground Truth

Human feedback is preserved as a raw assertion and separately adjudicated. The underlying defect may be a stale source, wrong entity, retrieval miss, or no defect at all.

4. Minimum Sufficient Evaluation

The Adaptive Router selects the cheapest reliable evaluator and stops once decisive. Rule can prove it → stop. Semantic model resolves it → stop. LLM only for material ambiguity.

5. Incident-Aware

Repeated correlated failures become one incident with one root repair — not hundreds of duplicate LLM investigations. Incident correlation short-circuits expensive re-diagnosis.

6. Governed Self-Healing

Only evidence-backed, bounded, reversible, policy-permitted fixes are eligible for automatic repair. Shadow validation and blast-radius tests run before any production promotion.

7. Compliance is Non-Negotiable

Mandatory AMC/regulatory controls (SEBI, SEC, FCA, ESMA) always run when applicable. They are never sampled away for cost reasons. Jurisdiction policy packs are independently versioned.

🧭 Evaluation Depth Ladder & Adaptive Router

The Adaptive Router is a deterministic, policy-driven orchestration engine — not an LLM agent. It selects the minimum sufficient evaluator using applicability, mandatory controls, evidence sufficiency, incident state, and explicit token/latency budgets. The ladder ensures the cheapest mechanism always runs first.

6-Level Evaluation Depth Ladder

LevelMechanism & Typical PurposeGen. Tokens% Traffic
E0 Telemetry Only — tool failures, empty retrieval, latency anomaly, schema violation, token anomaly. Healthy low-risk monitoring. Infrastructure outages resolved here. 0 ~100%
E1 Deterministic Rules — entity IDs, dates, numbers, citation integrity, source version, mandatory disclosures, guardrail checks, numeric reconciliation (NAV, TER, exit load). 0 ~100%
E2 Statistical / Cohort Checks — retrieval drift, anomaly detection, vector-graph-BM25 disagreement, inter-annotator agreement scoring, feedback deduplication clustering. 0 broad
E3 Semantic / NLI / Classifier — claim-evidence entailment, intent classification, contradiction detection, tone classification, semantic context coverage, advice-boundary classifier. ~0 generative 10–20%
E4 Bounded LLM Judge — nuanced factual synthesis, implicit claims, ambiguous feedback, multi-document contradiction, subtle recommendation language. Minimal EvaluationPacket only. controlled 2–5%
E5 Agent / Human Escalation — multi-step evidence acquisition, regulatory ambiguity, conflicting authoritative sources, compliance decisions requiring human sign-off. highest 0.1–0.8%
🛑
Preferred sequence — always cascade, never skip down E0/E1 → unresolved? → E2/E3 → unresolved & material? → E4 → actions/investigation required? → E5. The Router may skip irrelevant levels (e.g. infrastructure outage → E1 telemetry → STOP, no LLM useful).

5 Explicit Stop Rules (cost control)

STOP-1: Deterministic Proof

Authoritative structured source + exact entity + exact temporal context + deterministic mismatch → verdict established → STOP. No semantic model, LLM, or agent needed.

STOP-2: Evidence Absent

Required evidence missing + deterministic recovery unavailable → UNVERIFIABLE → STOP factual adjudication. Never ask an LLM to manufacture a verdict from incomplete evidence.

STOP-3: Known Incident

New observation matches an active confirmed incident with same causal signature → attach to incident → STOP repeated root-cause investigation. Massive cost saving during systemic failures.

STOP-4: Semantic Confidence

Semantic/NLI output within validated domain + confidence ≥ approved threshold → STOP. No LLM needed if the calibrated classifier is decisive.

STOP-5: Human Required

Policy says HUMAN_REQUIRED → STOP automated adjudication → route to compliance/HITL. LLM may assist with evidence summarisation but must not replace the required human decision.

STOP-6: Budget Exhausted

Token or latency budget exceeded before a verdict → SAFE_UNKNOWN or escalate. Never silently overspend the evaluation budget to force a result.

"Hallucination" is not a root cause — it is a symptom. Every failure is classified across four axes: What failed · How detected · Where it originated · What should heal it. This separation prevents unnecessary LLM calls and duplicate repair work.

Observable Symptom ≠ Technical Origin ≠ Repair Action

User: "Wrong answer / hallucination"
≠
System diagnosis: stale source
≠
Root cause: ingestion lag
→
Repair: source refresh + selective re-embed

Root-Cause Attribution Strategy (deterministic-first)

Wrong response observed
Was correct knowledge available? NO → Knowledge Gap (F04/F05)
Was it retrieved? NO → Retrieval Failure (F04)
Was it selected into context? NO → Context Engineering Failure (F03/F09)
Did the model use it correctly? NO → Generation / Reasoning Failure (F07/F10)
Was citation incorrect? YES → Citation Failure (F06)
💡
Most root causes are deterministic to diagnose. Source hash mismatch, index diff, retrieval replay, numeric comparison — no LLM needed. LLM is justified only when causal attribution remains genuinely ambiguous after all deterministic paths are exhausted.

Failure-Attribution Graph — Separate from Context Graph

🚫
Never merge failure data into the production context graph Operational noise leaks into retrieval · unverified hypotheses contaminate domain knowledge · feedback poisoning affects answer generation · retention/access-control requirements differ.
✅
Failure graph shares canonical IDs with context graph Same source_id, scheme_id, taxonomy_node_id — but separate access policies and serving behaviour. Failure intelligence informs routing and healing; it never becomes answer evidence by default.

🔧 Self-Healing RAG & Token Economics

Self-healing is a state-reconciliation and reconstruction problem — not an agentic reasoning problem. Known failures map to deterministic repair recipes. The vector DB and context graph are reproducible derivatives of the canonical source plane and can be safely rebuilt without LLM involvement.

🔍 RAG Retrieval (Hybrid: BM25 + Vector + Graph)

3 Levels of Self-Healing

Level 1 — Mechanical (near-fully deterministic)

Retry · restore · reconstruct · re-embed · re-index · deduplicate · repair metadata. Examples: missing embedding chunk, broken index, metadata hash mismatch. LLM tokens = 0.

Level 2 — Knowledge-Structure (mostly deterministic)

Entity canonicalization · graph constraint repair · source/version reconciliation · temporal relationship management · expire stale edges · recreate derived relationships with provenance.

Level 3 — Semantic (cascade: rules → classifier → LLM → human)

Ambiguous relation · conflicting narratives · missing ontology mapping · unclear entity resolution · semantic chunking problem. LLM is the last resort, not the first call.

Token Economics — 7 Compounding Optimisations

1. 📦 Batch Processing (25 items / call)

System prompt, graph context, few-shot examples amortised across 25 feedback items in one LLM call.

−70% prompt tokens

2. 🎯 Semantic Deduplication

Cluster similar corrections (cosine ≥ 0.85), evaluate cluster representative only, aggregate votes.

−40% items

3. 🔄 Shared Graph Context

Neo4j subgraph fetched once per batch, cached in Redis (1h TTL), injected as shared context for all 25 items.

−50% context tokens

4. 🚦 Conditional Routing

Pre-scoring: score > 0.95 auto-applies, score < 0.20 auto-rejects. ~60% of feedback never hits LLM.

60% skip LLM

5. 💾 Cached Few-Shot Examples

Domain-specific correction examples pre-computed, stored in Redis, retrieved once per cycle — not per batch.

−15% prompt tokens

6. 📝 Structured JSON Output

LLM constrained to compact JSON schema — no explanations, no markdown, no filler. Output tokens minimised.

−30% output tokens

7. 🔄 Incident Short-Circuit

New failures matching active confirmed incidents skip diagnosis entirely — attach to incident, reuse root cause.

Avoids repeat LLM calls

🏛️ Compliance Control Plane

Compliance is a first-class architecture dimension — not an afterthought. Mandatory AMC/regulatory controls always run when applicable and are never sampled away for cost reasons. Domain meaning lives in the AMC Taxonomy; approved obligations live in independently versioned Jurisdiction Rule Packs.

Critical Architectural Boundary

🗂️ AMC Taxonomy — Domain Meaning

What is this entity? What type of query? What claim was made? What evidence class is relevant? Examples: Scheme · NAV · TER · Benchmark · Risk Classification · Performance · Suitability-Sensitive Query

📋 Jurisdiction Rule Pack — Approved Obligations

Which controls apply? Which disclosure is required? Can this be delivered? Is human approval required? Which source hierarchy applies? Versioned, approved by compliance team, never LLM-generated.

🕸️ Failure-Attribution Graph — Operational Causality

What failed? What evidence proves it? Which component contributed? Is this part of an incident? What repair is eligible? Did the repair actually remove the cause?

⚠️
Jurisdiction alone is not enough. Applicability depends on: jurisdiction + legal entity + regulated capacity/role + product type + activity + communication channel + client/investor category + advice vs information + distribution arrangement + policy effective date. A US interaction does not simply mean "apply FINRA rules" — it depends on whether the entity is an SEC-registered adviser, broker-dealer, fund company, or distributor.
