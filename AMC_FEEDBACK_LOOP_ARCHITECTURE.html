⚡ 1 LLM Call→ JSON results
  • Batch processing: system prompt, schema, instructions paid once and amortised across 25 items −70% tokens
  • Shared graph context: Neo4j subgraph (affected nodes + 1-hop) fetched once per batch, not per item −50% context tokens
  • Structured output: response schema enforced — compact JSON only, no explanations or markdown filler −30% output tokens
  • Cached few-shot: correction examples stored in Redis per feedback type, retrieved once per cycle −15% prompt tokens
  • Confidence gating: only items with score ≥ 0.85 proceed to correction · 0.60–0.84 → human review · <0.60 → reject
  • Temperature: 0.2 · Max tokens: 2,000 · Model: claude-opus-4-8 · Baseline 2,100 tokens/item → ~188 tokens/item
💰
Token cost: Naive (1 call/item) = 2,100 tokens/item. Batched (25/call) = ~630. After dedup + routing = ~188. 91% total reduction.

✅ System Updatedfresh state
  • FAISS: invalidate embeddings for all entities that changed — forces re-embedding on next retrieval access
  • Redis query cache: DEL graph_context:{entity_hash} for all affected entity hashes
  • Entity resolver: clear canonical name → node ID mappings for renamed or merged entities
  • Neo4j traversal: clear cached graph paths passing through any modified node or relationship
  • Cache key pattern: hash(affected_entities, max_depth) · TTL: 1 hour for graph snapshots · Surgical — only affected entities, not full flush
🎯
Why surgical invalidation matters: A full cache flush would slow down all unrelated queries. Targeting only the changed entities keeps p95 latency stable for the rest of the system.
