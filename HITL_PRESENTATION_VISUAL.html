📋 Project Overview

A production-grade feedback loop that turns every user interaction into a knowledge graph improvement — automatically, efficiently, and safely.

What is HITL?

HITL captures thumbs-up / thumbs-down ratings and free-text corrections from users, buffers them in PostgreSQL, then runs an hourly batch evaluation through an LLM. High-confidence corrections are automatically committed to the Neo4j knowledge graph — so the system gets smarter with every interaction, at minimal LLM cost.

  • Non-blocking feedback capture (<100 ms)
  • Scheduled async evaluation — no user impact
  • Self-correcting Neo4j knowledge graph
  • Full audit trail + rollback capability
  • Token-optimised batch processing

Why Does This Matter?

  • Graph quality degrades without feedback — entities go stale, relationships break
  • Manual corrections don't scale — one engineer can't review every query
  • LLM calls are expensive — naive per-item evaluation costs 25× more
  • Users know best — domain experts spot errors LLMs miss
  • Compound gains — each correction improves future retrievals too

🔧 Core Components

Eight Python modules, each with a single clear responsibility. Designed to be deployed independently and swapped without breaking the pipeline.

📨

Feedback Collector

HTTP endpoint that validates, links to response metadata, runs NER + sentiment, stores to PostgreSQL — all in under 100 ms.

feedback_collector.py
💾

PostgreSQL Buffer

12 normalised tables + 6 cache tables. 90-day rolling retention. Indexed for batch reads. Acts as the source of truth for raw feedback.

postgres_client.py
📦

Feedback Processor

Aggregates votes, semantic deduplication (~40% reduction), builds 25-item batches with shared context payload.

feedback_processor.py
🤖

Batch Evaluator

Sends amortised batch prompts to the LLM. Parses structured JSON output. Confidence gating at 0.85 before passing to corrector.

batch_evaluation.py
📈

Graph Corrector

Validates correction plan, runs Neo4j transactions atomically, writes to audit log, triggers rollback on failure.

graph_corrector.py
🧠

Cache Manager

Surgically invalidates only affected FAISS embeddings, Redis keys, entity-resolver cache, and Neo4j traversal paths.

cache_manager.py
⏰

Orchestrator

APScheduler-driven 6-step coordinator. Configurable cron. Monitors health, retries failures, emits Prometheus metrics.

evaluation_orchestrator.py
📊

Feedback API Routes

FastAPI router: POST /feedback (non-blocking), GET /feedback/status, GET /feedback/stats. OpenAPI documented.

📥 Feedback Collection Path

The synchronous path from user click to database record. Designed to be invisible — zero latency impact on the query response.

8-Step Synchronous Flow

1 — User clicks 👍 or 👎 (optional comment)
2 — POST /api/feedback with response_id
3 — Validate: response_id exists, rating in range, comment length
4 — NER tagging: extract entities from comment (spaCy)
5 — Sentiment scoring: VADER polarity on comment text
6 — Intent classification: correction / confirmation / noise
7 — Async insert into PostgreSQL (non-blocking)
8 — Return { feedback_id, status: "recorded" } in <100 ms
🔑
Why non-blocking matters Steps 4–6 run in a background task (FastAPI BackgroundTasks). The HTTP response fires immediately after step 3. The user never waits for NLP or DB writes — they're fire-and-forget from the user's perspective.

⏰ Evaluation Cycle

Runs every hour as a background job. Invisible to users, asynchronous, and designed to process 500 feedback items in roughly 3 minutes.

6-Step Orchestrated Process

Step 1 — Fetch all pending feedback from PostgreSQL
Step 2 — Aggregate: group by entity + correction type, sum votes
Step 3 — Deduplicate: semantic clustering, keep highest-vote representative (−40% items)
Step 4 — Route: skip LLM if score > 0.95 (auto-apply) or < 0.20 (auto-reject) — 60% never hit LLM
Step 5 — LLM Batch Eval: send remaining in 25-item batches with amortised context
Step 6 — Apply corrections > 0.85 confidence → invalidate caches → record metrics → cleanup

🔄 Self-Correcting Knowledge Graph

The graph doesn't just store data — it learns from every interaction. Each correction cycle permanently raises the quality floor.

The Virtuous Cycle

👤 User gets a slightly wrong answer
👎 Rates it down, adds "Axis Fund NAV is wrong"
📊 Feedback buffered with context: entity=AxisFund, field=NAV
🤖 Batch LLM evaluates: "Update NAV property — confidence 0.92"
📈 Graph Corrector updates Neo4j node, clears FAISS index for AxisFund
✅ Next user asking about AxisFund NAV gets the correct value

Four Correction Types

➕

Add Entity

A fund, manager, or metric that doesn't yet exist in the graph gets created with properties and relationships.

✏️

Update Property

An existing entity has a stale value — NAV, AUM, expense ratio, risk rating — corrected in-place.

🔗

Add Relationship

A missing edge between entities added — e.g. "FundManager MANAGES Fund" that the ingestion pipeline missed.

🗑️

Remove Relationship

An incorrect edge deleted — e.g. a manager listed as managing a fund they left two years ago.

Safety Mechanisms

  • Confidence threshold (0.85) gates all automatic corrections
  • All corrections run inside atomic Neo4j transactions — partial failures roll back completely
  • Every change written to correction_execution_history with timestamp, confidence, and source feedback IDs
  • Human review queue for items in the 0.5–0.85 confidence band
  • Daily digest email summarises what was corrected (configurable)

💡 Token Optimisation

Seven compounding strategies that together reduce per-item token cost from 2,100 to ~188 — a 91% reduction.

1. 📦 Batch Processing

Evaluate 25 items in one LLM call. System prompt, schema, and instructions paid once and amortised.

−70% tokens

2. 🎯 Semantic Deduplication

Cluster similar corrections (same entity + same field), evaluate only the cluster representative. Votes are aggregated.

−40% items

3. 🔄 Shared Graph Context

Neo4j subgraph fetched once per batch and injected into the shared context, not per-item. Cached for 1 hour.

−50% context tokens

4. 🚦 Conditional Routing

Pre-scoring skips the LLM entirely for obvious cases: score > 0.95 auto-applies, score < 0.20 auto-rejects.

60% skip LLM

5. 💾 Cached Few-Shot Examples

Domain-specific correction examples pre-computed and stored in Redis. Retrieved once per cycle, not per batch.

−15% prompt tokens

6. 📝 Structured JSON Output

Response schema provided up-front. LLM returns compact JSON only — no explanations, no markdown, no filler.

−30% output tokens

7. 🧠 Graph Snapshot Caching

A lightweight Neo4j snapshot (affected entity neighbourhood only) cached hourly. Avoids expensive graph traversal mid-batch.

−20% latency
